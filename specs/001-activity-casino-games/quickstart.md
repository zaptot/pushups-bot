# Quickstart: проверка казино локально

## Требования

- Go из `go.mod`, Node.js 20+.
- `.env` с рабочим `DATABASE_URL`, `DISCORD_TOKEN`, `GUILD_ID` (как для бота).
- Добавить в `.env`:
  ```
  ACTIVITY_PORT=8080
  ACTIVITY_DEV_USER_ID=<твой Discord ID>
  ```

## Запуск

```bash
go run .
cd activity && npm install && npm run dev
```

Открыть адрес, который покажет Vite (обычно `http://localhost:5173`). Вход происходит автоматически от имени `ACTIVITY_DEV_USER_ID`.

## Сценарии проверки

1. **Рулетка (US1).** Поставить 20 на красное. Результат на колесе совпадает с ответом, выигрыш 40 или 0 фантиков, в `casino_bets` появилась строка. `/status` и `/top` не меняются.
2. **Повтор (SC-006).** В DevTools повторить запрос `POST /api/roulette` с тем же `id` 10 раз — в `/history` одна запись.
3. **Plinko (US2).** 16 рядов, высокий риск, ставка 37. Шарик попадает в лунку из ответа, выплата ≈ 37 × множитель.
4. **Блэкджек (US3).** Сыграть партию; обновить страницу посреди партии — партия продолжается с того же места. Оставить партию на 2 минуты — она завершается сама.
5. **Рокетка (US4).** Ставка 50, забрать около x2 — выигрыш ≈ 100. Вторая ракета с автовыводом x1.5 и закрытой вкладкой — итог записан в `casino_bets`.
6. **Без режима разработки (US5).** Убрать `ACTIVITY_DEV_USER_ID`, перезапустить — `POST /api/session` без `code` получает `401`.

## Автоматические проверки

```bash
go test ./... -run Casino
```

Проверяют возврат каждой игры (рулетка 97,3%, Plinko 99% по всем 27 таблицам, рокетка 99% ± 1 п.п.), правила блэкджека, случайное округление и единственность начисления при повторе (последнее — только при заданном `DATABASE_URL`).

## Внутри Discord (позже, когда решим с хостингом)

1. Developer Portal → приложение бота → Activities: включить, URL Mapping `/` → публичный адрес.
2. Добавить в `.env` `DISCORD_CLIENT_SECRET`, убрать `ACTIVITY_DEV_USER_ID`.
3. Для теста без хостинга: `cloudflared tunnel --url http://localhost:5173` и его адрес в URL Mapping.
